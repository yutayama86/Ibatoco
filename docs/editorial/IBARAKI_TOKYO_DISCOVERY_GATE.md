# イバトコ｜茨城44市町村＋東京の茨城関連イベント Discovery Gate

更新：2026-11-17　起点：Issue #635

## 目的と対象
「茨城の重要イベントが公開記事に上がってこない」をP0運用欠陥として扱う。対象は**茨城県内44市町村**に加えて、**東京で開催される茨城の自治体・産品・地域文化・観光・事業者・スポーツ等に関連するイベント**。茨城県外を網羅する一般イベントメディアにはしない。

「網羅」を名乗らない。監視の存在、HTMLの取得成功、イベント発見、事実確認、記事公開はそれぞれ別の状態。

## 処理経路（導入済み／改修対象）
1. `data/editorial/official-source-watch.json` の公式一覧・主催者をread-only巡回。GitHub Actions 06:20 JST → artifact。アクセス不能・不完全表示・ページ分割は明記。
2. `scripts/official-source-watch.mjs` がHTMLリンク名を**未検証候補**として取り出す。登録済みイベントの `officialUrl` / `relatedOfficialUrls` に照合。未一致だけを `unregisteredCandidateLinks` に表示。
3. ChatGPTの朝7時 Growth & Revenue OS 2.0で候補の個別公式ページを開き、日程・場所・主催・更新有無を検証。保存場所は `data/editorial/event-registry.json`。発見したが記事にしないものも残す。
4. 既存URL・11月イベントまとめ・季節ハブ・関連記事と照合し、「新記事／既存追記／経過観察／見送り」を判断する。写真・画像・SNS投稿の無許諾転載はしない。
5. オーナー承認／既存公開ポリシーに従い、PR → CI → マージ → デプロイ。記事とワークフローの承認は別。

## 監視の地理と層
- **茨城県内**：県公式観光、44市町村のイベント/観光発表、観光協会、開催会場/主催者、スポーツクラブ、商工会等。市町村固有の公式URLが設定されていない地域は `municipalityCoverage.missing` に残し、**未監視**と明示する。県全域ポータルを44市町村の監視完了として数えない。
- **東京都内の茨城案件**：茨城県の営業戦略・食/観光の発表、茨城をたべよう、IBARAKI sense、茨城ゆかりの出展者/主催者、東京の会場・商業施設（駒沢、二子玉川、銀座、下北沢等）の告知。場所が東京というだけで茨城関連と判定しない。主催/出展者の一次情報による関連性を要する。
- **東京開催のイベントを台帳に入れるとき**は `municipality: "tokyo"`（現行スキーマでは県外・その他）とし、関係する茨城市町村を `notes` に記録する。将来的に `venuePrefecture` と `originMunicipalities` を構造化する場合は専用のスキーマ変更PRとする。
- **参照例**：東海村 IMOフェス2026、潮来 Riverside Illumination 2026、東京・駒沢 茨城をたべよう収穫祭2026、東京・二子玉川 いばキュン！マルシェ2026。

## レポートの意味・NG
- `fetched` は指定された公式URLのHTMLを取得した、のみ。イベントを全部拾えたことにはならない。
- `candidateLinksFound` はリンク見出しのキーワードヒット。イベント確定ではない。
- `unregisteredCandidateCount` は公式URLの**文字列完全一致がない**候補で、未掲載の確証ではない。イベントと断定せず確認する。
- 前回のartifact/レポートが手元にない場合 `firstSeenInCurrentReport = null`。これを「今日初めて公開された」と表現しない。
- `tokyoIbarakiSourceCount` は東京側の設定件数。監視網の網羅性は示さない。
- GitHub Actions artifactが未取得、外部サイトが403/500/JSレンダリング、年版が古い、リンク見出しだけ、PDFしかない場合は状態を分けて当日記録。
- 対象イベントがなかった日の「未検出」と、確認が失敗した日の「未確認」を混同しない。

## 既知の不足と次工程（Issue #635）
- 44市町村の直接監視は未達（今回の2追加でも完全ではない）。各市町村の実在する現行公式一覧URLを検証し、カテゴリ別に段階追加。取得不能なページは代替一次情報を記録する。
- 個別イベントページの本文の取得・日時/変更の正規化はまだ自動化していない。候補リンクを人/ChatGPTが確認し、推測で日時・開催可否を記入しない。
- GitHub scheduled runはクリーンなチェックアウトのため前回のartifactが自動では引き継がれない。「初出」判定は未導入。次フェーズでは履歴の安全な永続化とURL重複整理を検討する。
- 東京案件のカバレッジは県/食/アンテナショップ等から開始。地域団体・商工会・会場告知の広がりは未完了。
- 追加サービス料金ゼロ、公開サイトへの攻撃的巡回なし、公式一次情報、広告/編集記事の区別を維持。
