## 5. 構造化データとして管理できるか

施設名・所在地・営業時間・休み・料金・予約の要否・予約方法・年齢条件・所要時間・駐車場台数・最寄りIC/駅・確認日・出典URLは、4施設とも同じ項目で揃えられる。今回は既存の記事frontmatter（picks・keyPoints・sourceUrls）に入れ、新しいデータファイルはつくらない。理由：施設数が4と少なく、二重管理になるため。施設が8〜10件を超え、検索（Discovery OS）や地図で再利用する段階になったら、`docs/DISCOVERY_OS.md` に沿って共通データへの切り出しを検討する。

## 6. 収益化・更新・自動化

- 収益：現時点で提携・広告・有料掲載はない（BookingGuide のリンクはすべて公式）。食品メーカーの工場見学は無料施設が中心で、直接の送客報酬は見込みにくい。周辺の宿泊・観光・直売所への回遊を、既存の地域記事で受ける。新しい契約は行わない。
- 更新：各社の公式ページを年2回（春・秋）と、休館・改装の発表時に確認する。手作業は1回あたり4ページ程度。
- 自動化：新しい定期ワークフローは追加しない。既存の鮮度・事実の検査（`npm run verify`）の範囲で管理する。
