## 目的と根拠

- 解決する読者課題：「今日・今週末、茨城で何をやっているか」を知りたい人に、確認済みの開催情報を一番早く・一番多く返す
- 現状データ（GSC 公式 API、`performance-snapshot.json`、28日：2026-10-22〜11-18）
  - `/events/` 全体：表示 16,766・クリック 210・CTR 1.3%・平均 10.1位
  - 「茨城（県）＋イベント・祭り＋今日・今週末・週末・明日」の語句 140種：**表示 11,107・クリック 141・CTR 1.3%・平均 8.3位**（例：「茨城県イベント(今日)」2,102表示・8.0位、「茨城 イベント 今日」1,186表示・8.3位、「今日のイベント 茨城」866表示・8.4位）
  - サイトで最大の検索語のまとまり。TOP（`/`）はこの語句で表示されておらず、`/today/` も検索表示がないため、ページ同士の食い合いはない（TOP は指名検索「イバトコ」だけを担う。2026-11-22 オーナーと合意）
- 競合（2026-11-22 に検索結果を確認）：上位はウォーカープラス。「今日・明日・今週末」を別URLに持ち、1日あたり25〜33件を掲載。差は**件数**と**日付つきの即答**
- 期待値（推測）：平均8.3位→3位前後になり CTR が 8〜10% 程度なら、この語句群だけで28日 900〜1,100クリック（現状 141）。月間100万PVに対しては一部であり、同じ型（毎年・毎週くり返す大きな検索意図に1つのハブで答える）を紅葉・花火・イルミネーション・初詣・梅まつり等へ広げる最初の1つとして位置づける

## 方針

イバトコの差別化は「公式で確認できたものだけ」。件数を増やしても、この基準は下げない。自動生成のURLを大量に index しない（AGENTS.md・Discovery OS）。

### 第1段階（action: 20261122-events-hub-today-answer）：冒頭で「今日」に日付つきで即答し、構造化データを足す

1. `ThisWeek`（`/events/` 冒頭の「今日・今週末、茨城でできること」）の見出し直下に、**閲覧日の日付と件数**を出す一文を追加
   - 例：「11月22日（日）に開催中・開催予定のイベント 14件（公式で日程を確認済み）」
   - 日付と件数は既存のクライアント側再計算（`ThisWeek.astro` の script）と同じ基準・同じタイミングで出す。ビルド時の日付を固定で書かない（公開処理が止まった日に古い日付が残るのを防ぐ）。日付の扱いは `src/lib/date-only.js`・`Asia/Tokyo`
   - 0件の日は一文ごと出さない（「今日は何もありません」とは書かない。既存方針）
2. `/events/` の JSON-LD に `ItemList` を追加（既存の `CollectionPage`・パンくずは変えない）
   - 要素：これから開催・開催中のイベント記事（終了・noindex・未確定を除く）を開催が近い順に最大30件。各要素は `ListItem`（`position`・`url`・`name`）のみ。`Event` の詳細は各記事側の既存 JSON-LD に任せ、ここで重複・矛盾させない
3. 変えないもの：title（すでに「茨城のイベント｜今日・今週末の開催と月別一覧｜イバトコ」）、description、H1、URL、canonical、v42 の見出し、`/today/`

### 第2段階（action: 20261122-events-listings）：確認済みイベントの「短い掲載」で件数を増やす

記事を書くほどではないが公式で日程・会場を確認できたイベントを、**個別URLを持たない短い掲載**として `/events/` と `/today/` の「今日・今週末」に出す。

- データ：新規 `data/editorial/event-listings.json`。1件＝`{ id, name, municipality, venue, startDate, endDate, time?, fee?, officialUrl, officialLabel, checkedAt }`。日付は `YYYY-MM-DD`（日本の暦日）
- 表示：`ThisWeek` の各区分に記事と並べて出す。記事と見分けられる表示（「公式情報へ」の外部リンク・確認日つき）。記事がある場合は記事を優先し、同じイベントを二重に出さない（`event-registry.json` の名称＋開始日で重複判定）
- index：個別ページは作らない。`/events/` の本文として読まれる
- 運用：ChatGPT の日次の外部監視で、開催14日以内の確認済みイベントを追加する。終了日を過ぎたものは表示しない（データは残す）
- 目標：**「今日・今週末」に出る確認済みの件数を、週末で25件以上**（現状は開催中の期間ものを含めて十数件）
- `scripts/editorial-os.mjs` の検証に、`officialUrl`・`checkedAt`・日付形式の必須チェックを追加（欠けたらCIエラー）

## 検証（判定基準）

GSC の「茨城（県）＋イベント・祭り＋今日・今週末・週末・明日」の語句群（`/events/`）で判定する。季節で検索量が動くため、表示回数ではなく**平均順位と CTR** を見る。

- 第1段階（公開後28日）
  - 継続：語句群の平均順位が 8.3位 → 6位以内、または CTR 1.3% → 2.5% 以上
  - 見直し：どちらも動かない（順位 ±1位以内・CTR ±0.3ポイント以内）→ 第2段階（件数）を先に進める判断材料にする
  - 差し戻し：平均順位が 2位以上悪化
- 第2段階（掲載開始後28日）
  - 継続：週末の確認済み件数 25件以上を4週続け、語句群の平均順位が 5位以内
  - 見直し：件数は満たしたが順位が動かない → 競合との差（日付別URL等）を再調査。自動生成URLの大量 index は引き続き行わない
