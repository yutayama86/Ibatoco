## 目的と根拠

- 現状データ（GSC 公式 API、`performance-snapshot.json`、28日：2026-10-22〜11-18）
  - 上位200ページの平均 CTR は 3.1%。うち **表示1,000以上・CTR 2%未満が22ページ（表示 約7万）**
  - 5〜10位にいながら CTR が1%前後のページが多い
- 原因の仮説（3つ。ページごとに当てはまるものを直す）
  1. **検索語が title の先頭にない**：例「常総新花火 2026 場所」で探されているのに、title に「場所」「会場」がない
  2. **title が長く、スマホで検索語の部分が切れる**：現状45〜50字。スマホの検索結果で見えるのは先頭30字前後
  3. **title だけで答えが完結し、押す理由がない**：例「…セット900円」「駐車無料」。答えに加えて、記事にしかない判断材料（違い・注意点・混む時期）を title に出す
- 変えるのは **title だけ**（description・本文・URL・H1 は変えない）。1つの変数だけ変えて、効いたかを判定するため

## 実装指定

- 対象ファイル：各記事の frontmatter の `title` のみ（`src/content/news/chikusei-premium-voucher-second-2026.md`、`src/content/events/ushiku-daibutsu-guide.md`、`src/content/events/tsukubasan-jinja-guide.md`、`src/content/events/ibaraki-airport-parking-access-guide.md`、`src/content/events/joso-shin-hanabi-2026.md`）
- 記事テンプレートは frontmatter の `title` を `<title>` と H1 の両方に使う（`src/pages/events/[slug].astro`・`news/[slug].astro`）。これまでの title 改善（`seo-changes.ts` の metadata 変更）と同じく H1 も同じ文になる。2026-11-08 のオーナー決定は「デザインの見本コピーに置き換えない」ことで、検索のための title 改善はその範囲外
- OG画像の文言が title から自動生成される場合は、生成物を同じ PR に含める（`npm run og:cards`）
- `src/data/seo-changes.ts` に1ページ1エントリで記録（kind: `on-page`、experimentType: `metadata`、change に旧→新の title）
- 5ページは同じ日に公開する（判定期間をそろえるため）

## 変更禁止

- description・本文・URL・canonical・構造化データ（title と同じ値で自動生成されるものを除く）
- 記事テンプレート・回遊まわり（Issue #683 の判定まで）
- 新しい事実の追加。title の事実は上の根拠の範囲だけ

## 検証（判定基準）

- 観測：公開から28日（metadata の観測窓14日は最低限。判定は28日）
- 指標：各ページの主な検索語での CTR と平均順位（GSC、公開前28日と公開後28日）
- 判定（ページごと）
  - **効いた**：CTR が1.5倍以上、かつ平均順位の悪化が1位以内
  - **効かない**：CTR の変化が ±20%以内
  - **戻す**：CTR が下がった、または平均順位が2位以上悪化 → 旧 title に戻す
- 第1波全体で3ページ以上が「効いた」なら、同じ原則で第2波（残りのページ）を進める。2ページ以下なら、原因の仮説を見直してから第2波を作る
