## 目的と根拠

- 解決する読者課題：検索で来た読者は、日時・駐車場など1つの答えを得て離脱している。そのすぐ後に必要になる情報（行き方・近くで同じ日にできること・同じ種類の次の開催）への道がない
- 現状データ（GA4 公式 API、`performance-snapshot.json`）
  - 1訪問あたりPV（views/session）：直近7日 1.147（11/12〜11/18）、前の7日 1.107。回遊実験 `20260921-growth-next-reads` の開始前基準 1.1535（9/14〜9/20）から**変わっていない**
  - 前週からのPVの伸び（+17.7%）のうち、訪問数の増加による分が78%。回遊による分は22%
  - 「次に読む」枠（`GrowthNextReads.astro`）：最も良い週（10/11〜10/17）で表示2,324・クリック160（6.9%）。クリック率は合格だが、**クリック数そのものが小さすぎる**
- なぜ今の枠では届かないか（計算）
  - 直近7日のセッションは5,584。views/session を1.5にするには、週に約1,950PVの上乗せが必要（5,584×(1.5−1.147)）
  - 今の枠の上乗せは週160前後。クリック率を2倍にしても約320で、必要量の2割に届かない
  - 枠は記事の最下部（情報源・協賛枠の後）にあり、表示されるのは訪問の半分以下。**置き場所が問題で、候補の選び方の問題ではない**
- この施策を今選ぶ理由：回遊は新しい記事なしで全ページに効く唯一のレバー。月間100万PV（2027年1月）と11月10万PVのどちらにも効く

## 方針（3段階。1段階ずつ、前の段階の判定が出てから次へ）

同時に複数の回遊施策を入れると、どれが効いたか分からなくなる（直近90日の改善変更のうち77件が観測中で、判定できていない）。**1段階＝1つの変更**とし、判定が出るまで同じページ群の回遊・テンプレートには触らない。

### 第1段階：答えの直後に「次の一手」（最優先）

- 置き場所：`/events/[slug]/` の `#facts`（開催情報）セクションの直後。スマートフォンで1〜2画面目に入る位置
- 中身：リンク最大3件。読者がその次に知りたいことの順に、ルールで選ぶ（手で選ばない。一人運営で維持できること）
  1. **行き方**：記事の市町村・会場に対応する交通ガイドがあれば1件（例：鹿島臨海鉄道・常磐線特急・高速バスのガイド）。なければ出さない
  2. **同じ日・近くで**：同じ市町村か隣接市町村で、開催期間が重なる・または常設のスポットガイド1件（`findRelated` の市町村重み）
  3. **同じ種類の次**：同じカテゴリ（花火・紅葉・イルミネーション等）で、まだ終わっていない次の開催かまとめ（ハブ）1件
- 見た目：リンク3件の小さな枠。見出しは「次に調べること」。広告と誤認させない（PR・協賛と明確に分ける）
- 既存の「次に読む」枠（最下部）は**変更しない**（比較のため）

### 第2段階：終了したイベントの冒頭に「次の開催」

- 終了判定（`eventLifecycle === 'ended'`）のページで、ページ上部に「このイベントは終了しました」と、同じ種類で終わっていない次の開催・まとめへのリンク1〜2件
- 根拠：土浦花火（前の7日324→直近7日10）、帰り道（338→3）のように、終了後も検索から来る読者を次へ渡せていない
- 既存URL・本文・titleは変えない（記事の事実は残す）

### 第3段階：本文中の文脈リンク

- 「行く前に」「よくある質問」の該当箇所（駐車場・アクセス・周辺）から、既存の常緑ガイドへ本文リンク
- 記事ごとの手作業になるため、第1・第2段階の結果で効果が確認できてから、PVの多い記事に限って行う

## 検証（判定基準）

数字はすべて GA4 公式 API の確定値。A群とB群は同じ期間で比べる。

- 7日後（途中確認・中止判定のみ）
  - `next_step_click` / `next_step_view` が1%未満 → 選び方か見た目に問題。中止して見直す

- 28日後（本判定）

  - **改善して再実験**：差が +0.03〜+0.10（効いているが小さい）。選び方を1点だけ変えて、もう28日
  - **中止**：差が +0.03未満、またはB群より低い。第2段階へ進む
