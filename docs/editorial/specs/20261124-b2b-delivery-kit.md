## 目的

「少ない工数で高い利益」（実効時給2万円以上）を、仕組みで実現する。2027年2月の独立までに、最初の案件を決めて納品できる状態にする。一度作れば案件ごとに使い回せる資産にする。

## 大前提：顧客の情報は公開リポジトリに置かない

- `yutayama86/Ibatoco` は**公開リポジトリ**。顧客名・顧客の数字・契約・見積・請求の情報を、ここのコード・データ・Issue・PR・Actions のログに一切置かない
- 顧客ごとの作業は、オーナーが作る**非公開リポジトリ**（仮称 `ibatoco-works`）で行う。GitHub の非公開リポジトリと Actions の無料枠の範囲で動かす（追加費用ゼロ原則）
- 公開リポジトリには、顧客情報を含まない「仕組み」（汎用のレポート生成・サイトの型）だけを置く

## 1. 書類の型（最優先：12月中旬まで）

最初の商談・契約に必要。独立前の12〜1月に案件を決めるために、最初に作る。

- 置き場所：非公開リポジトリ `ibatoco-works/templates/`（料金は公開済みだが、顧客ごとの書類は非公開）
- 作るもの
  1. **提案書の骨子**：現状 → 課題 → 提案（プラン）→ 進め方 → 料金 → 実例（イバトコの実データ）→ 条件。プランは `src/data/services.ts` の内容と一致させる
  2. **見積書**：プラン・作業上限・期間・税別金額・有効期限。協力者への委託分は別行
  3. **業務委託契約書（準委任）**：範囲と作業上限・成果を保証しないこと・追加作業は別途見積・協力者への再委託の可否・秘密保持・知的財産・支払い・中途解約（月額は3か月から）・責任の上限
  4. **秘密保持契約書（NDA）**
  5. **現状診断レポートのひな形**：検索・AI検索・運用の現状、改善の優先順位、次の提案
- 契約書・NDAは、**使う前に専門家（弁護士）の確認を受ける**。Claude の作る文面はたたき台
- 完了条件：オーナーが1件の商談で、提案書・見積書・契約書を30分以内に用意できること

## 2. 顧客向けレポートの自動作成（12月末まで）

現状診断（10万円）とコンサル・SNS運用・スポンサーの月次レポートの作業を、ほぼゼロにする。

- 仕組み：イバトコで動いている `scripts/google-api-daily.mjs`（GA4・GSC の取得）と `src/lib/analytics-report.mjs`（集計・判定）を、**顧客のプロパティを引数で受け取れる汎用部品**にして公開リポジトリに置く（顧客情報は含まない）
- 実行：非公開リポジトリの GitHub Actions で、顧客ごとに月1回（と診断時に1回）実行し、HTML のレポートを作る。結果は Actions の成果物（非公開）として保存し、オーナーが確認して顧客に渡す
- 顧客のデータへのアクセス：顧客に、GA4 と Search Console へ**閲覧のみ**の権限を、イバトコ専用のサービスアカウントに付けてもらう。編集権限は求めない
- 秘密情報：サービスアカウントの鍵は非公開リポジトリの Secret にだけ置く。作成・登録はオーナーが行う（AGENTS.md：Claude は Secret を作成・出力しない）
- レポートの中身：PV・訪問・検索の表示とクリック・主な検索語・AI検索からの流入・前月比・改善した施策と結果・次にやること。取得できない値は「未取得」（0で埋めない）
- 完了条件：イバトコ自身のプロパティでレポートが作れること（顧客ゼロでも動作確認できる）

## 3. Web制作の型（2027年1月中旬まで）

Web制作（80万円〜、想定25時間）を型で短くする。

- 置き場所：公開してよい汎用の型（顧客情報なし）。非公開にするかはオーナーが決める
- 中身：イバトコと同じ技術（Astro）で、検索・AI検索向けの基本設定を最初から入れる
  - 構造化データ（Organization・LocalBusiness など）、サイトマップ、OGP、llms.txt、パンくず
  - スマホ対応・表示速度・アクセシビリティの基本
  - イバトコの品質監査（`quality-audit`・`tech-audit` の汎用部分）を流用した公開前チェック
- 公開先：Cloudflare Pages など無料枠で始められる先を標準にする（顧客の契約・費用は顧客負担）
- 完了条件：型から1ページのサイトを2時間以内に立ち上げ、公開前チェックが通ること

## 4. 問い合わせから入金までの記録（/control/）

- GA4 で取れる「/biz/ の表示・相談ボタンのクリック・問い合わせ送信」を /control/ に BtoB の区画として出す（公開リポジトリのデータだけで作れる範囲）
- 商談・成約・金額・入金は顧客情報を含むため、**公開リポジトリに記録しない**。非公開リポジトリの台帳で管理し、/control/ には件数・合計額だけを手で反映するか、反映しない（オーナーが決める）

## 変更禁止

- 有料のSaaS・APIの導入（請求書・契約管理のツールを含む）。必要なら無料の範囲で代替し、有料はオーナー承認後
