## 監査した現行構成
- Astro + Cloudflare Workers、`BrandBase.astro` に共通ヘッダー・フッター・SEO/GA4の入口がある。
- スタイルは `src/styles/global.css` にブランドトークン、`src/styles/interior.css` と `interior/*` に下層の共通構造、ページごとのAstro内スタイルも存在する。TOPと下層は意図的に分離されている。
- `scripts/build-web-fonts.py` と `fonts.generated.css` が日本語フォントをUnicodeサブセット化している。TTFファイルがソース中で大きいことだけを理由に、本番へ11MB転送されると断定しない。
- `astro.config.mjs` は `compressHTML: true`, `inlineStylesheets: 'auto'`, `prefetch.defaultStrategy: 'hover'`。viewport全件prefetchへ戻さない。
- `npm run verify` に Astro type-check、fact/OG監査、ビルド、品質・技術・セキュリティ・データ・リポジトリ・計測・編集監査、SEO観測窓、単体テスト、UI smoke、visual diffがある。
- 売上・計測の混同は禁止。クリック、送客、ASP発生、確定売上は別指標。

## 今回の非破壊的変更
1. `--interior-sky` の値 `#dcecff` を既存のブランド変数 `--color-sky` に参照統一。表示色・CSSセレクタは不変。
2. ニュースカード画像に `decoding="async"` を明示。レイアウト、カードサイズ、URL、画像リソースは不変。

## 次期改修前の固定ルール
- **デザイントークン正本**: `global.css` の `--color-*`、文字サイズ・余白等を基本とする。色コードが異なる値まで機械的に統合しない（特にTOP、下層、スポーツ・インターナショナル）。
- **ページパーツ**: カード、見出し、メタ情報、ボタン、パンくず、予約/PR表示を共通要素別に棚卸し。新コンポーネントは複数ルートへの重複が根拠として出た場合にのみ提案。
- **表示変更の判定**: 320 / 375 / 430 / 768 / 1280 / 1440pxで、横スクロール・見出し改行・カード高さ・FOUC・CLSを確認。CI成功だけで本番UX合格とはしない。
- **性能測定**: Web Vitals/Lighthouseの実測が無い限り「高速化◯%」などは主張しない。フォント・画像・JavaScript・CSSのネットワーク転送サイズとLCP要素を計測してから順に変更する。
- **記事とSEO**: URL、canonical、structured data、meta、観測窓中の本文を、全体デザイン整理の名目でまとめて変更しない。
- **収益・計測**: booking/sponsor CTAのDOM位置・GA4 event、広告表記、計測属性を守る。
