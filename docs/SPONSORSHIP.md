# 協賛（PR）の運用

協賛の営業・掲載・報告の正本。料金は `src/data/sponsorship.ts`、掲載の登録は `src/data/sponsors.ts`。
事業者へ案内するときは、掲載イメージと最新の料金を記載した `/sponsor/` を共有する。

2026-11-10 更新。

---

## 1. イバトコ地域サポーター

企業・店舗・団体向けに、**19,800円／3か月（税別）**でトップページ下部の協賛欄に社名・ロゴ・公式サイトへのリンクを1件掲載する。掲載社数に上限を設けず、掲載期間中の事業者を同じ形式で紹介する。

1. `/sponsor/apply/` で申込みを受け付ける。事業者名、担当者の連絡先、公式サイトのURLを確認する。
2. 掲載許諾のあるロゴを返信メールで受け取り、掲載内容・料金・日本時間の開始日と終了日について合意する。
3. `SPONSOR_SLOTS` に1件登録する。`pages: ['/']`、`image` にロゴ、`text: ''`、`cta: '公式サイトを見る'` とし、開始日・終了日を入れる。掲載は両日を含む。
4. 掲載開始後に一括で請求する。振込期限は請求書発行月の翌月末日。表示とクリックの実測は希望があれば案内する。
5. 終了時に継続の希望を確認し、次の期間と料金に双方が合意したら更新する。枠の表示は掲載期間に従って切り替わる。

個別の企画や以前のお見積りは、協賛の相談窓口で受け付ける。成立済みの契約には当時の規約と合意条件を適用する。

## 2. 個別に合意したイベント協賛枠を掲載する

### 受け取るもの

- 事業者名
- 紹介文（120字以内。事実だけ。「No.1」「必ず」「最安」など根拠のない断定は載せない）
- リンク先（https://）とリンクの文言（例「空室を確認する」）
- 写真1枚（任意。**先方に利用の許諾があるもの**だけ）→ `public/images/sponsors/` に置く
- 掲載する記事（イベントの記事）と掲載期間

### 登録

`src/data/sponsors.ts` の `SPONSOR_SLOTS` に1件足す。

```ts
{
  id: 'tsuchiura-hotel-example-2026-11',   // 集計の主キー。掲載後に変えない
  name: '（事業者名）',
  pages: ['/events/tsuchiura-hanabi-2026/', '/events/tsuchiura-hanabi-2026-kaeri/'],
  text: '（120字以内の紹介文）',
  url: 'https://example.com/',
  cta: '空室を確認する',
  start: '2026-10-01',
  end: '2026-11-07',
  image: { src: '/images/sponsors/example.jpg', alt: '（写真の説明）', width: 800, height: 600 },
},
```

- 期間は**日本時間の暦日**。開始日・終了日を含む
- 誤り（id重複、120字超、https以外、開始＞終了、同じページ・同じ期間に4枠以上）は**ビルドが止まる**
- 本番は push でしか再ビルドされない。開始・終了の切り替えは画面側でも日本時間で判定するので、終了日に作業は要らない
- 終了した登録は消さずに残してよい（集計のIDを残すため）

### 表示

- 記事の「予約・確認先」のあと、情報源の前に出る（`SponsorSlots.astro`）
- 枠の冒頭に「PR 協賛（広告）｜この枠は広告です。記事の内容とは関係なく、掲載の順位や評価も変わりません。」を必ず出す。**この文言を消さない**
- リンクは `rel="sponsored noopener"`。`noreferrer` を付けないのは、協賛先が自分の解析でイバトコからの流入を確かめられるようにするため
- JavaScriptが動かない環境では出さない（読者の側に倒す）

## 3. 個別に合意したPR記事を掲載する

- `src/content/articles/` に `disclosure: pr` と `disclosureNote`（誰の依頼か・対価があること）を書く。スキーマが `disclosureNote` を必須にしている
- 事実は通常の記事と同じ基準で一次情報と照合する。先方の資料でも、確認できない数値は載せない
- 関連するイベント記事・地域ページから導線を張る（Editorial の本文に宣伝文を混ぜない。関連リンクとして置く）
- 多言語版は販売を止めている（確認者がいないため）。再開するときは、公開前にネイティブの確認を必ず通す

## 4. 計測と報告

### 送っているイベント

| イベント | いつ | 主なパラメータ |
| --- | --- | --- |
| `sponsor_view` | 協賛枠が画面に半分以上入った（1枠1回） | `sponsor_id`, `slot_position`, `source_page`, `page_type`, `municipality` |
| `sponsor_click` | 協賛枠のリンクを押した | 上と同じ ＋ `link_url` |
| `outbound_booking_click` | 予約・確認先のリンクを押した | `link_url`, `link_provider`, `link_kind`, `source_page` |

### GA4 のカスタムディメンション（2026-09-27 登録済み）

管理 → データの表示 → カスタム定義 → カスタムディメンションを作成（範囲はすべて「イベント」）

| ディメンション名 | イベントパラメータ |
| --- | --- |
| 協賛ID | `sponsor_id` |
| 送り元ページ | `source_page` |
| リンク先URL | `link_url` |
| リンクの提供元 | `link_provider` |

2026-09-27 に、プロパティ `properties/547804264`（測定ID G-2DNYX7CSK6）へ `sponsor_id`・`source_page`・`link_url` を登録した。`link_provider` は登録済みだった。**登録した日より前のデータには付かない**ので、送り先別・送り元別の集計は 9/27 以降の分から出せる。
（Apps Script から登録する場合は `docs/GA4_MEASUREMENT.md` の手順どおり、本番の集計プロジェクトではなく一時プロジェクトで行う）

### 報告に出す数字

| 数字 | 取り方 |
| --- | --- |
| 枠の表示回数 | `sponsor_view` のイベント数（協賛IDで絞る） |
| クリック数 | `sponsor_click` のイベント数（協賛IDで絞る） |
| クリック率 | クリック数 ÷ 表示回数 |
| 掲載ページの閲覧数 | 掲載ページの `screenPageViews`（ページパスで絞る） |

Apps Script（GA4 Data API）での取り方の例：

```js
// 協賛IDごとの表示とクリック
AnalyticsData.Properties.runReport({
  dateRanges: [{ startDate: '2026-10-01', endDate: '2026-11-07' }],
  dimensions: [{ name: 'eventName' }, { name: 'customEvent:sponsor_id' }],
  metrics: [{ name: 'eventCount' }],
  dimensionFilter: { filter: { fieldName: 'eventName', inListFilter: { values: ['sponsor_view', 'sponsor_click'] } } },
}, 'properties/<GA4のプロパティID>');
```

報告は数字をそのまま出す。推計・見込み・他社比較は書かない。期間の最新日は未確定のことがあるので、**前日までで締める**。

## 5. 守ること

- 2023年10月から、広告であることを隠した表示（いわゆるステマ）は景品表示法の規制対象。協賛枠・PR記事は必ず「PR」と文言で示す
- 協賛の有無で、記事の事実・評価・並び順を変えない。編集記事の推薦は売らない
- 同じ記事に同時に載せる協賛枠は3社まで。トップページの地域サポーターは掲載期間中の全社を紹介する
- 成果（来店・売上・順位）を約束しない
