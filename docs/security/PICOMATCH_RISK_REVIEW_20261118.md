# 未修正picomatchの期限付きリスク許容（2026-11-18 オーナー承認済み）

2026-11-18 JST。対象PR #644。これは脆弱性の修正ではなく、公開更新の全面停止を避けるための、範囲を限定したリスク許容の提案です。

## 確認済みの事実

- GHSA-fc5q-39xc-vjpf / CVE-2026-112366 は、利用者が与えた特定のglobを正規表現へ変換して評価する場合のReDoS。npm最新版4.0.7にも未修正。4.0.7と2.3.2がビルドツールの依存経路に存在します。
- Astroは7.4.12へ更新済みの提案で、他の直接XSS/画像処理/XML警告は解消します。残るhighは同じpicomatchの警告が依存元へ伝播したものです。
- wrangler.jsoncはworker/index.jsと静的distを配信します。Workerはnpm/Nodeのglobモジュールをimportせず、読者からglobを受け取って評価するコードもありません。Astroサーバー/開発サーバーは公開しません。
- これにより現在確認した公開リクエストからの到達経路はありませんが、ツールの未修正状態は残り、あらゆる将来の到達可能性を否定するものではありません。

## 代替案との比較

- 上流のnpm修正版を待つ：最も単純ですが、記事の事実訂正・別のセキュリティ修正・計測更新まで同時に停止します。修正版の期日は未発表です。
- 古いAstroへの大幅downgrade、dev依存への移動、未評価のfork：互換性または監査範囲の新しいリスクを生むため採用しません。
- 本提案：未修正の事実を警告と生JSONに残し、1件のadvisoryと実体バージョン/構成が一致する場合だけ、短期間の許容を可能にします。

## 提案する制限

- 期限：2026-11-21 00:00 Asia/Tokyoで自動失効（11月20日まで）。最大7日を超える設定も拒否。
- 対象：このadvisoryのhighだけ。別のhigh、critical、同じライブラリに追加された別advisory、循環/欠落した依存関係、npm取得エラーは必ず失敗。
- package-lock.json・Worker・wrangler設定・Astro設定のSHA-256を固定。picomatchの実体パスとバージョンも固定。構成が変われば再評価まで停止。
- npm auditの生結果・元の終了コードはreports/security/dependency-audit.jsonへ保存し、CIにも未修正の警告と失効日を出す。all-dependenciesのcritical監査は従来どおり継続。
- 設定の初期状態はpending-owner-approval。PR CIではレビュー用に続行できますが、mainへのpush・定期実行・ローカルでは承認前設定を拒否します。

## 承認後の手順

オーナーが本PRの期限付き例外を明示承認した場合だけ、設定をapprovedへ変更し、承認者と承認日時を記録します。必須CI成功後にsquashでマージし、既存のDeploy productionと本番SHA/ページ確認を行います。承認前にmainへ入れません。

毎朝の既存Growth OSで正式な修正版の有無を確認。修正版が出たら依存更新とCIで本例外を撤去します。期限を自動延長しません。攻撃経路または別advisoryが見つかった場合も公開停止して再評価します。

## 検証

- 期限境界・新しいhigh/critical・欠落/循環レポート・構成変更・承認なしmain拒否等を専用テストで検証。
- PR CIの許容は脆弱性が直ったことを意味しません。承認前の本番デプロイは不可です。
- full verify / CodeQL / UIの実行結果はPRへ記録します。未実施の検証を成功とは扱いません。
