# 成長基盤リポジトリ監査

最終更新: 2026-09-20

## 結論

既存実装を作り直す段階ではない。Astro Content Collections、44市町村、イベント、ニュース、スポーツ、店舗、送客、計測、品質監査まで既に一続きになっている。今後は既存URLと検索実績を守りながら、重複を減らし、計測結果から1ページずつ改善する。

## 現状

- Astro 7 / TypeScript strict / 静的出力
- `src` 配下215ファイル、ビルド325ページ
- `npm run verify` でファクト、OG文字、型、ビルド、内部リンク、SEO、構造化データ、データ参照を検査
- コンテンツ: `articles` / `events` / `news` / `places` / CSV `stores`
- 行動導線: `BookingGuide` / `BusinessCta` / `ArticleNextSteps` / アフィリエイト判定
- 地域資産: 44市町村境界、地域別ガイド、テーマ、市町村・店舗・イベントの相互参照
- 運用資産: Decap CMS、ニュース作成ルール、SEO変更履歴、スポーツ更新状況、収益機会抽出

## 今回の是正

1. Astro診断の未使用コード9件を解消した。
2. 空の `places` コレクションが全ページで出していた反復警告を、公開されない明示的プレースホルダーで解消した。
3. プレースホルダーは `draft: true` / `sample: true` / `noindex: true` をスキーマで強制した。
4. `/agency/ → /biz/` の恒久転送に対し、転送先canonicalを正しい状態として技術監査が認識するようにした。
5. READMEのサイトマップを現在のイベント、ニュース、スポーツ、44市町村構成へ更新した。
6. 611行の `content.config.ts` を、登録点と `core` / `news` / `events` / `foundations` に分割した。
7. 1,920行の `interior.css` を、読み込み順を固定した7つの責務別CSSへ分割した。
8. `repository-audit.mjs` を追加し、スキーマ再集中・CSS順序変更・不要なバックアップファイルをCIで検知するようにした。

## 残る課題と優先順位

### P0: 検証と運用の信頼性

- `npm run verify` の警告を原則ゼロに保つ。
- `http://` の外部リンクは、公式サイトのHTTPS疎通を確認できたものだけ移行する。
- PR単位を「投資対象1ページ＋必要な共通部品」に限定する。
- 分析対象、変更対象、評価対象のURLを一致させる。

### P1: コードの責務分割（基盤対応済み）

- 20KB超のページ・コンポーネントは、見た目ではなく責務境界で分割する。
- `src/content.config.ts` は登録点のみとし、共通スキーマ、記事・店舗、イベント、ニュースへ分割済み。今後も登録点へ実装を戻さない。
- 日付、URL、公開判定、構造化データ生成を `src/lib` に集約する。
- `themes.ts`、`area-guides.ts`、`ibaraki-geo.ts` は中核データなので、機械的分割や自動整形をしない。

### P2: 成長編集ループ

1. GSCとGA4から投資対象を1ページ選ぶ。
2. 既存ページなら新規記事を作らず、検索意図・内部リンク・CTAを改善する。
3. `npm run verify` と差分レビューを通す。
4. 公開後7日と28日で、検索クリック、CTR、行動クリック、問い合わせを評価する。
5. 改善が再現した要素だけ共通部品へ昇格する。

## 変更しないこと

- URL整理を目的とした一括リネーム
- 検索実績を確認しない記事統合・削除
- 架空情報や推測日付を使う量産
- パートナーを優遇するランキング
- 安全・災害・健康情報への不適切な収益導線
- 重いクライアントJS、ログイン、CRMの先行実装
