# B. 掲載依頼・編集記事・PR記事・広告商品の事業設計

- 作成：2026-11-01／Claude Code
- 前提
  - 協賛の営業は停止中（`docs/IBATOCO_UNIFIED_GROWTH_OS.md`）。この文書は**設計だけ**で、営業候補の収集・提案資料・送信は行っていない
  - 価格・契約条件・新しい広告枠の公開は、すべてオーナー承認事項
- 既存の正本（この設計はこれを置き換えず、足りない部分を補う）
  - `/about/pr-policy/`（PR・広告の方針）
  - `docs/SPONSORSHIP.md`（協賛の運用）
  - `src/data/sponsorship.ts`（料金）
  - `docs/editorial/specs/20261011-self-serve-listing-pilot.md`（セルフサービス掲載の検証仕様）
- 「推測」と書いた数値は、根拠のある見積もりであって実測ではない

## 0. 結論

1. **分類は「対価の有無」と「内容を誰が決めるか」の2軸で決める。** URL を有料か無料かだけで分けない。既存の区分（編集記事・パートナー・PR・協賛枠）をそのまま使い、「提供資料に基づく編集記事」という扱いを明文化する（§1）。
2. **公開方針と実装に食い違いがある。** 方針ページは「すべての記事に区分を表示」と約束しているが、/news/ と /events/ には区分の表示もデータ項目も無い。PR を受ける前に、ここを埋めるのが最優先（技術設計は C）。
3. **仮説価格は既存の公開料金より大幅に安く、1時間あたりの粗利が低い。** そのまま公開すると、既存の料金表（/sponsor/）と矛盾し、手作業が売上に比例して増える。営業を再開するときは、工数の少ない**協賛枠を主力**にし、PR 記事は問い合わせが来たときだけ受ける形を推奨する（§3）。
4. **今の需要は小さい。** 事業者向け導線は表示 460 回に対してクリック 1 回、確認できた B2B 問い合わせは 0 件（9/28〜10/4）。確定売上の台帳も 0 件。商品を増やすより、受付と表示の仕組み（費用ゼロ）を先に整え、問い合わせが来たら同じ手順で処理できる状態にするのがよい。

## 1. 分類基準

### 1-1. 判定の2軸

| | 内容は編集部が決める（事実確認の依頼だけ受ける） | 依頼者が内容を決める、または承認する |
|---|---|---|
| **掲載の対価なし** | **編集記事**。資料提供・招待・無償提供があれば個別に開示する | **受けない**（無償でも、依頼者が内容を決めた表示は事業者の広告にあたる可能性がある。専門家確認事項 L-2） |
| **継続的な関係（支援・協業）あり、記事ごとの対価なし** | **パートナー**。関係を記事内に明示する | **PR** として扱う |
| **記事の制作・掲載に対価あり** | **PR**（方針ページの定義どおり、金銭の対価が掲載に直接結びつけば Partner ではなく PR） | **PR** |
| **記事とは別の広告枠** | **協賛枠**（既存。`SponsorSlots`） | — |

**用語**

- **事実確認の依頼**：日付・料金・名称などの誤りの指摘を受けること。評価・表現・掲載順の修正要求には応じない。応じた時点で PR として扱う
- **個別開示**（方針ページの既存ルール）：招待（無料・割引）、商品の提供、取材費用の負担があれば、区分にかかわらず記事内に書く
- **提供資料に基づく編集記事**：プレスリリースや主催者資料を一次情報として使い、編集部が裏取りと編集をした記事。次の2点を記事内に明記する
  - 「主催者提供資料と公開情報を基に作成、現地取材なし」
  - 画像の提供元

### 1-2. 種別と URL

| 種別 | URL | 一覧・推薦への掲載 | 検索・構造化データ |
|---|---|---|---|
| 編集ニュース | `/news/` | 通常どおり | NewsArticle。news-sitemap の対象 |
| イベントガイド | `/events/` | 通常どおり | 既存どおり |
| PR・タイアップ | `/pr/<slug>/`（最初の受注時に新設） | 編集記事の推薦枠（人気・次の行き先など）には入れない。PR の一覧と、関連ページの「PR」と明示した枠からだけリンクする | Article（NewsArticle にしない）。news-sitemap から除外。外部リンクは `rel="sponsored"` |
| 協賛枠 | 記事内の枠（既存） | 既存どおり（1記事3社まで） | リンクは `rel="sponsored noopener"`（既存） |
| 事業者情報 | 将来検討（`/place/` 等の既存データ） | 基本情報は無料・編集判断。有料の拡張は表示上も区別する | — |

- 既存記事の一括移動・URL 変更はしない。区分の変更は表示の追加で行う
- 記事の URL を変えると、リダイレクト・SEO 履歴・観測窓の手当てが要る
- PR の URL を `/pr/` に分けるのは、有料か無料かのためではない。「依頼者の目的で作った記事」を編集ニュースの一覧・ニュース用サイトマップ・推薦から構造的に外すため
- PR 記事を noindex にする必要はない。ただし外部リンクには必ず `rel="sponsored"` を付ける

## 2. 横田医院の掲載事例（`/news/yokota-iin-haikyo-tour-2026/`）

| 観点 | 記録から確認できること | 記録に無いこと（推測しない） |
|---|---|---|
| 情報源 | 主催者（京都オカルト商会）の公式サイト・プレスリリース資料、つくば市の公開資料、チケット販売ページ（sourceUrls 5件） | — |
| 取材 | 記事に「主催者提供資料と公開情報を基に作成した開催前の紹介。現地訪問・インタビューは行っていない」と明記 | — |
| 画像 | 主催者提供の告知用ビジュアル（イメージ）と明記（imageCaption・ogImageAlt・本文） | 画像の利用許諾の範囲（期間・SNS での二次利用の可否）の書面 |
| 対価 | — | 金銭・招待券・現物などの対価の有無 |
| 編集関与 | 公開後に読みやすさの修正 PR が2本（#462、#464） | 主催者が原稿を事前確認・修正したか |

**分類の判断**

- 対価が無く、主催者が内容を決めていなければ：**編集記事（提供資料に基づく紹介）**。URL は維持し、技術設計 C の `sourceRelationship: organizer-materials` を付ける
- 招待・無料券などの便益があったら：編集記事のまま、**その事実を記事内に個別開示**する
- 掲載に金銭の対価があった、または主催者が内容を承認していたら：**PR** として表示を変える
  - URL は維持する（既存 URL の変更はしない方針）
  - PR の表示（タイトル周辺・冒頭・末尾）と `rel="sponsored"` を付け、news-sitemap から外す
  - これは既存記事の訂正にあたるので、オーナー承認事項

**オーナーに確認すること**：上の「記録に無いこと」の3点（対価の有無、事前確認の有無、画像の利用許諾の範囲）。回答を非公開の案件台帳（C §3）に記録する。

**今後の類似案件の基準**：同じ「主催者からの情報・画像提供」でも、次の3点がそろったときだけ編集記事として扱う。

1. 対価がない
2. 主催者は事実確認しかしていない
3. 掲載するかどうかを編集部が決めた（掲載を約束していない）

## 3. 収益商品

### 3-1. 既存の公開料金と仮説価格

既存（`src/data/sponsorship.ts`・/sponsor/ で公開中、税別）：

- イベント協賛枠 19,800円
- PR記事（素材提供型）59,800円
- シーズン協賛 198,000円（約3か月）

依頼書の仮説価格（税込 → 税別）：

- PR記事ライト 16,500円 → 15,000円
- PR記事＋SNS 33,000円 → 30,000円
- 年間パートナー 132,000円 → 120,000円から

仮説価格は既存の PR 記事より約75%安い。採用するなら、公開中の料金表・媒体資料と同時に改定する必要がある（価格変更はオーナー承認事項）。

### 3-2. 商品ごとの比較

工数はすべて**推測**。根拠は次の2つ。

- docs/SPONSORSHIP.md の見積もり（PR 記事 2〜3時間、協賛枠 30分）
- 横田医院の記事（提供資料型）が、初回公開のあと修正 PR を2本要したこと

時間あたり粗利は「税別売上 ÷ 工数」で、外注費は0、AI は既存の契約内で追加費用0と仮定した。振込手数料は先方負担とした。カード決済を入れると3%前後が引かれる（決済の導入自体がオーナー承認事項）。

| 商品 | 税別売上 | 提供範囲（案） | 工数（推測） | 時間あたり粗利 | 継続性 | 運用負担・リスク |
|---|---:|---|---:|---:|---|---|
| 通常の情報提供 | 0円 | 情報を受け取る。掲載は保証しない。掲載すれば編集記事 | 判定 0.25h／件（掲載時は通常の編集工数） | — | 記事の素材にはなる | 断る連絡の手間。不採用の基準を公開しておく |
| PR記事ライト（仮説） | 15,000円 | 素材提供型1本、先方の事実確認1回、30日後の実測報告1回 | 4h | 約3,750円 | 単発 | 工数が売上に比例する。安価な PR が増えると編集の信頼が下がる |
| PR記事＋SNS（仮説） | 30,000円 | 上記に、イバトコ SNS 2投稿（PR 表記付き）と報告を追加 | 5h | 約6,000円 | 単発 | SNS の PR 表記と、画像の二次利用許諾が必要 |
| 年間パートナー（仮説） | 120,000円（月1万円相当） | 提案：協賛枠を年4シーズン差し替え、PR記事2本、四半期の実測報告 | 13h／年 | 約9,200円 | **継続（MRR）** | 1年分の価値提供が必要。解約・返金の条件を決めておく |
| イベント協賛枠（既存） | 19,800円 | 記事内の PR 枠1つ、期間指定 | 0.5h | 約39,600円 | 季節ごとに更新 | データ1件の追加で掲載・切り替え・計測まで済む |
| PR記事（既存） | 59,800円 | 素材提供型、修正1回 | 4h | 約15,000円 | 単発 | 価格に見合う露出があるかを説明できる必要がある |

### 3-3. 判断

- **協賛枠が最も「資産になる仕組み」に近い。**
  - 1件あたりの工数が最小で、オーナーの手作業への依存（Founder dependence）が低い
  - 需要の山（あんこう祭は直近7日で 1,586 views）に乗せられる
- **PR 記事は人の手間で売る商品。** 一人運営の原則（売上に比例して手作業が増える設計は原則採用しない）と相性が悪い。受けるときは次の条件にする
  - 問い合わせが来たときだけ受ける
  - 本数に上限を設ける（例：月3本）
  - 範囲を固定する
- **年間パートナーは企業価値に最も効く**（継続収益）。ただし、今の閲覧規模（10月1〜28日で GA4 15,375 views）で年 12万円に見合う露出を約束できるかは不明。実測の報告だけを約束し、成果は約束しない
- **価格を下げて公開するのは推奨しない。** 下げる根拠になる需要の実測（問い合わせ0件）がない。安い PR を入口にすると、読者に「売られている媒体」と見られ、長期の信頼を損なうおそれがある
- 営業の再開時期・価格・対象はオーナーが決める。再開の判断材料として、次を推奨する
  1. 区分表示の実装（C）が本番に出ている
  2. 受付から報告までの手順（§4）を、無料の情報提供で一度通しで回している
  3. 掲載先ページの実測（表示・クリック）を、協賛枠の報告形式で出せる

## 4. 標準ワークフロー（11段階）

非公開の情報（契約・金額・連絡先）は公開リポジトリに置かない（C §3）。

| # | 段階 | 担当 | やること | 記録先 | 次へ進む条件 |
|---|---|---|---|---|---|
| 1 | 受付 | ChatGPT（一次対応）／オーナー | 既存フォーム（/submit/・お問い合わせ）か、オーナーに届いたメール | 非公開の案件台帳に「受付」行を作る。公開の `docs/records/business-inquiries.csv` には件数と状態だけ（氏名・連絡先・社名は書かない） | 依頼の種類（情報提供／PR 希望／協賛枠希望）が分かる |
| 2 | 依頼者の確認 | ChatGPT | 主催者・提供者が実在するか、権限があるか（公式サイト・登記・自治体の告知） | 案件台帳 | 実在と権限が確認できる。できなければ止める |
| 3 | 一次情報の検証 | ChatGPT | 日付・料金・会場・条件を公式の一次情報と照合する（AGENTS.md の基準） | 案件台帳、記事の `sourceUrls` | 確認できない事実は掲載しない |
| 4 | 広告性・対価の判定 | オーナー（最終） | §1-1 の2軸で判定。金銭・現物・招待・便益を聞き取って記録する | 案件台帳（対価の種類と金額は非公開） | 区分が決まる |
| 5 | 掲載可否と優先順位 | ChatGPT が案を出し、オーナーが決める | 編集記事なら読者需要（GSC・季節）で判断。PR なら§1-2 の掲載条件と本数の上限 | 案件台帳 | 掲載する／しないを依頼者へ回答できる |
| 6 | 写真・ロゴの利用許諾 | ChatGPT が文案、オーナーが確認 | 権利者・利用範囲（Web・SNS・期間・改変）を書面（メール可）で受ける。第三者の写真・ロゴ・キャラクターは許諾なしに使わない | 案件台帳（許諾メールの保存場所） | 許諾の範囲が記録されている |
| 7 | 編集記事か広告商品かの決定 | オーナー | 有料なら見積もり・範囲・掲載期間・修正回数・解約条件を書面で合意 | 非公開の契約記録 | 合意がある（PR の場合） |
| 8 | 制作・事実確認 | ChatGPT（必要なら Claude） | 編集記事は news-post の手順どおり。PR は区分表示・`rel="sponsored"`・先方の事実確認1回 | Draft PR | `npm run verify` と `verify:article` が通る |
| 9 | PR・CI・承認・公開 | ChatGPT → オーナー | PR → CI（build・Analyze）→ オーナー承認 → マージ → Deploy production → /build.json で確認 | GitHub | 本番に区分表示が出ていることを確認 |
| 10 | 計測 | ChatGPT | 掲載ページの閲覧、`sponsor_view`・`sponsor_click`、外部リンクのクリック、SNS の表示（取得できるものだけ） | 案件台帳（報告日）、確定売上は `data/editorial/revenue-ledger.json` | 前日までで締めた実測値だけを報告する |
| 11 | 更新・掲載終了・問い合わせ | ChatGPT／オーナー | 掲載期間の終了（PR は終了日に表示を外すか「掲載終了」とする）、訂正（訂正方針どおり）、解約・返金（契約どおり） | 案件台帳、訂正履歴 | 終了処理と最終報告が済む |

## 5. 法務・広告表示の確認項目

**専門家確認事項**は、法的判断が要るので、契約・公開の前に弁護士等に確認する（費用が発生する場合はオーナー判断）。それ以外は、既存の方針と公開されている一次情報から運用で守れる事項。

| ID | 項目 | 運用で守ること | 専門家確認事項 |
|---|---|---|---|
| L-1 | 景品表示法（ステルスマーケティング告示） | 2023年10月1日から、事業者の広告であることが分かりにくい表示は不当表示（消費者庁）。PR・協賛枠は「PR」「広告」の文言で示す。対価や提供を受けた事実は文章でも明示する（運用基準が例示する方法） | 規制の対象は主に広告主（事業者）。媒体側の責任範囲、契約で広告主に表示の遵守を約束させる条項の書き方 |
| L-2 | 「事業者の表示」に当たるか | 無償提供でも、依頼者が内容を決めたら PR と同じに扱う（§1-1）。評価や星の数を条件にした依頼は受けない | 無償の招待・資料提供だけで、編集部が内容を決めた場合の扱いの最終確認 |
| L-3 | 不当表示（優良誤認・有利誤認） | PR 記事の中の効能・最安・No.1 などの主張は、編集記事と同じく一次情報で確認できたものだけ載せる | 依頼者の主張を載せた場合の媒体の責任 |
| L-4 | リンク属性 | PR 記事・協賛枠の外部リンクは `rel="sponsored"`（Google の方針）。編集記事の通常の外部リンクには付けない | — |
| L-5 | 著作権・肖像 | 提供画像は権利者と利用範囲を書面で受ける。人物が写る写真は本人の同意の有無を確認する。撮影者表記の要否を確認する | 二次利用（SNS・媒体資料）の許諾文言のひな形 |
| L-6 | 個人情報 | 問い合わせの氏名・連絡先は公開リポジトリ・公開 CSV に書かない。保存場所はオーナー管理の非公開の場所だけ。プライバシーポリシーの利用目的の範囲で扱う | 案件台帳の保管期間と削除のルール |
| L-7 | 契約（掲載期間・修正・解約・返金） | 書面で合意：掲載開始・終了日、修正回数、掲載後の訂正は編集部の判断、中途解約と返金の計算、**成果（来店・売上・順位）を保証しない**こと | 契約書・利用規約のひな形、消費者契約法の適用の有無（相手が個人事業主の場合） |
| L-8 | 対価・便益の記録 | 金銭・現物・招待・割引を案件ごとに記録し、記事の開示と一致させる | — |
| L-9 | 依頼者の編集関与 | 事前確認は事実の誤りの指摘だけ。それを超える修正に応じたら PR に区分を変える | — |
| L-10 | 税・請求 | 請求書の記載（税込・税別）、インボイス登録の有無に応じた請求の形 | 適格請求書発行事業者の登録の要否（**オーナーの登録状況が不明なので確認が必要**） |
| L-11 | 業種の制限 | 医療・医薬品・健康食品・酒類・投資・金融は、各業法の広告規制があるので当面は受けない | 受ける場合は業種ごとの規制確認 |
| L-12 | 外注 | 制作を外注する場合、発注の書面化と支払期日 | 2026年1月施行の改正法（中小受託取引適正化法）の適用の有無 |

## 6. 将来の継続収益モデル

| 段階 | 主な収益 | 仕組み | 次の段階へ進む条件（提案） |
|---|---|---|---|
| 0. 今（営業停止中） | アフィリエイト（承認済み） | 区分表示・受付手順・案件台帳を整える（費用0） | C の最小実装が本番に出る |
| 1. 問い合わせが来たら受ける | 協賛枠、PR記事（本数上限つき） | 既存の協賛枠の仕組み、`/pr/` の新設 | 問い合わせ・受注・入金が実績として記録される（フォーム送信を受注と数えない） |
| 2. 季節の協賛 | シーズン協賛・年間パートナー（継続） | 需要の山（花火・紅葉・あんこう・梅・桜）ごとの協賛枠を、前年の実測で提案 | 継続率と、1社あたりの月次工数が一人で回る範囲 |
| 3. セルフサービス | 事業者情報の有料拡張・協賛枠の自己申込 | 既存の検証仕様（20261011）のゲートどおり | 採算ゲート（確定売上 − 手数料 − 工数）を満たす |

**企業価値への寄与**：継続収益（MRR）と、季節ごとの実測データ（どのページが何 views を持つか）が資産になる。PR 記事の本数は資産にならない。編集の信頼が落ちると、全体の価値が下がる。
