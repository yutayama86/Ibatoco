# 公式情報ウォッチ（段階導入・第1段階）

## 目的
2026-11-14のコーヒーフェス見落としを再発防止するため、発見元の取得成否を「イベントがなかった」と混同しない。既存のDiscovery Gateは発見後の台帳と記事を検査するもので、外部サイトを巡回しない。両者は別の責務。

## 第1段階で実装したもの
- `data/editorial/official-source-watch.json` の10の公開公式URLを順に読み取る（既知のコーヒーフェス詳細、県北月間一覧、県観光ポータル、水戸市・つくば市・鹿嶋市・古河市・筑西市・八千代町のイベント情報など）。**44市町村全域のカバーではない。**
- `node scripts/official-source-watch.mjs` で読み取り結果をJSON出力。 `--write` を付けると `reports/editorial/official-source-watch.json` に保存する。
- `node --test scripts/official-source-watch.test.mjs` でHTML文字抽出・日付言及・HTTP失敗と未検証の区別をテストする。
- 取得失敗、403などのHTTP失敗、空/JS描画、対応外コンテンツを区別し、取得時刻を残す。直前の保存結果がある場合に本文ハッシュの変更を判定し、公式URL完全一致の既存台帳項目を参照表示する。**ページ全体の変更はイベント変更の証拠ではない。**検索語と日付文字列は**候補シグナル**であり開催確定の根拠ではない。
- 公式ページのHTML内にある同一ドメインのリンクから、監視語に一致するリンク見出しを**未検証候補**として最大40件抽出。前回レポートからの初出と、イベント台帳の公式URL完全一致を報告する。リンクの有無だけでは新イベント・未掲載の確定としない。\n- 公式の一次情報で日時・会場・料金・出演者などを人/ChatGPTが再確認した後にだけ、既存 `data/editorial/event-registry.json` へ追記する。

## 未実装・禁止事項
- これは手動実行可能な試験用監視器で、**GitHub Actions・毎朝7時に接続されていない**。既存の自動タスクの調査指示と混同しない。
- 日付・出演者・会場の構造化抽出、RSS/サイトマップ対応、44市町村ソース一覧、出演者・ブランド起点の逆引き、PRとの照合、イベント単位の名称・日付・会場照合、同じイベントの別公式URLや別名判定は次段階の検証対象。\n- リンク候補は1ページ最大40件、静的HTMLで同一オリジンのみ。別ドメインの主催者や出演者の情報を網羅できるわけではない。
- `src/data/areas.ts` に登録された44市町村と、直接の公式ソースが設定されている市町村を照合し、未登録市町村を報告する。県全域のポータルは44市町村すべての直接監視とみなさない。\n- 取得した公式HTMLをそのまま公開しない。契約・利用規約に反する大量アクセス、SNSログイン回避、外部有料APIはしない。記事公開や台帳への自動書き込みも行わない。
- 今回は `.github/workflows/` に触れない。自動スケジュールに繋ぐ際はAGENTS.mdに従い別途個別承認が必要。

## 合格判定と次の段階
1. このPRのCI（build、CodeQL）と `npm run verify` の合否を確認する（未実行は未実施として報告）。
2. ソースごとの取得成否と失敗件数を日次で観察し、継続して取得できるページだけを対象拡大する。取得できないサイトは障害として記録する。
3. 巡回対象台帳に市町村・施設・出演者・作品・ブランドの公式URLを追加し、週次で「未巡回」「掲載漏れ」「新規候補」を照合する。候補の存在を確認しないまま新記事を量産しない。
4. 毎朝のGrowth OSからGitHubの監視結果を確認できる経路を設計する。自動連携の実装・公開は別途承認が必要。
